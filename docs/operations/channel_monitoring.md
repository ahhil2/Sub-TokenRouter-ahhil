# 渠道监控

`/monitor` 展示管理员选定的公开分组的请求统计。访客和登录用户使用相同的数据。登录用户进入应用布局，保留左侧栏；访客使用公开页头。管理员在页面的“监控配置”中勾选分组并设置展示状态，通过分组管理维护名称、展示品牌、排序和倍率。读取接口为 `GET /api/v1/channel-monitors`，使用公开面板 IP 限流。

## 展示与权限

每个分组是一张卡片，卡片按 `display_brand` 分区。品牌为空时使用分组名。查询返回管理员勾选且 active、非 exclusive、未删除、绑定了 active 提供商的分组，最多 200 个，按分组顺序和 ID 排列。未配置、清空配置或新增分组时，默认不展示。分组失去公开资格后，缓存最多再保留 30 秒。失去公开资格的分组仍可在管理表单中保留配置，恢复资格后继续展示。

管理员接口 `GET/PUT /api/v1/admin/channel-monitors/config` 使用管理员认证、面板限流和审计。GET 返回未删除分组的配置和公开资格，PUT 的 `groups` 数组包含 `group_id`、`enabled`、`status`。保存会拒绝重复 ID、已删除或不存在的分组、超过 200 条的配置、缺失数组及非法状态。空数组表示全部隐藏。普通用户和访客不能读取或修改管理配置。

展示状态支持 `auto`、`operational`、`degraded`、`failed`、`maintenance`。自动状态按实际可用率计算，手动状态在卡片上标记“手动”。指标和历史色块继续使用实际请求统计。配置以 JSON 数组保存到 `settings.channel_monitor_groups`，不新增 schema。保存成功后当前进程立即清空快照缓存，其他进程的快照最多在 30 秒后更新。

响应包含分组名称、品牌、倍率和聚合指标。用户身份、API Key、提供商标识、上游地址、错误详情和请求正文保留在管理员接口。

前端展示 90 分钟窗口，划分为 20 个连续时段，每格 270 秒。每 30 秒刷新一次。隐藏标签页暂停轮询，返回页面后刷新。查询失败时保留上一份快照并显示过期提示。空时段显示灰色和“暂无数据”。正常状态块使用 `#41A988`，鼠标悬浮、键盘聚焦或触屏点击后显示该时段的可用率、缓存率和首 Token 延迟。

该页面按用户提供的参考截图使用局部圆角和间距变量，桌面三列，中等宽度两列，手机一列。全局控件样式保持由 UI 规范维护。

## 指标定义

- 可用率：成功数除以成功数与失败数之和。成功来自 `usage_logs`，失败来自 `ops_error_logs`。按分组、API Key 和 request ID 去重，已经有成功用量记录的同请求错误不重复计入。排除 count-tokens、业务额度限制和无上游错误的 401/403。正常阈值为 95%，零成功率为异常，其余为波动。
- 缓存率：缓存读取 Token 除以输入、缓存写入和缓存读取 Token 的总和。窗口汇总使用 Token 加权，不能平均各格百分比。
- 首 TOKEN P50：从成功请求的 `timings` 计算有效 TTFT 的中位数，与运维统计共用 `usageTTFTSQL`。`upstream_stream` 为真时，按 `ttft_mode` 选择首事件或首输出时间，减去上游开始时间；缺少时间或结束早于开始的记录不参与延迟统计。整个窗口直接计算中位数，不能平均各格中位数。升级前没有 `timings` 的记录仍参与可用率和缓存率统计，TTFT 显示为空。
- 所有时间段采用入库记录的 `created_at`，范围左闭右开。界面时间使用浏览器时区。空分母和无延迟样本返回 JSON `null`，界面显示为 `—`。

## 查询与维护

`ops/channel_monitor.go` 负责 30 秒进程缓存、并发请求合并和 5 秒查询超时。`ops/postgres/channel_monitor.go` 一次查询聚合整个窗口和各时段。关闭 `ops_monitoring_enabled` 后返回停用状态，防止用缺失的错误记录显示可用率。

页面读取已有记录，运行时不向模型发送探测请求。数据库 schema 无新增内容。请求量大时先检查查询耗时和时间范围索引，保持固定窗口与单次刷新缓存。

测试覆盖公开分组过滤、去重、窗口端点、加权缓存率、中位数、无数据、缓存与取消、接口错误脱敏、状态块悬浮和键盘访问。
