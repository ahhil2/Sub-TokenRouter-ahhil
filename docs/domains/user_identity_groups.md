# 用户身份分组

身份分组由管理员分配，入口位于分组管理的“身份分组”页签。身份是用户权益，普通分组继续承载路由、模型和访问权限。

<a id="membership"></a>
## 成员关系

`identity_groups` 保存三个固定身份：`bonus_5`（5%额外）、`bonus_10`（10%额外）、`ahhilai`（AHHilAI）。`user_identity_memberships` 以用户和类别为主键；充值类别最多一档，定价类别可以与充值类别同时存在。

批量分配在事务内按用户 ID 顺序锁用户，检查全部用户存在，再替换或移除成员关系。移除操作匹配指定身份，所以移除 5% 身份不会移除已经变成 10% 的用户。修改前后的成员信息写入 `identity_group_changes`，事务成功后失效用户认证缓存。

身份组不授予普通分组访问权限。AHHilAI 的倍率为空时继承普通分组默认值，新普通分组自动出现在倍率表中。

<a id="pricing"></a>
## 消费倍率

`identity_group_rates` 保存 AHHilAI 对普通分组的覆盖倍率。billing 按个人专属倍率、身份倍率、普通分组默认值的顺序解析余额消费倍率；覆盖值可以是零。个人倍率管理读写 `user_group_rate_multipliers`，有效倍率读取将个人覆盖与身份覆盖合并。

网关资金准入、结算、创作台、批量图片和用户分组价格展示使用同一有效倍率读取能力，查询失败返回错误。网关在调用上游前检查身份倍率是否可读取。有效倍率直接读取数据库，身份变更后的请求读取新值。异步图片任务使用提交时保存的计费快照。团队请求按付款主体的身份解析，订阅承担部分使用套餐规则。已解析的零倍率在订阅超额转余额时保持为零。

<a id="recharge"></a>
## 充值与退款

正数余额兑换码按兑换事务内读取的充值身份赠送 5% 或 10%。赠送使用十进制计算，按 8 位小数四舍五入。兑换记录的 `recharge_snapshot` 保存基础额度、身份标识、赠送比例、赠送额度和实际到账额度；兑换码面额保持原值。

在线余额订单在下单时保存相同结构的快照。付款和补单按照这个快照发放，支付内部兑换通过独立上下文传入快照。历史订单的空快照表示无加赠。管理员调账、并发兑换、订阅、注册赠送和返利转入使用各自的既有规则。

邀请返利基数是加赠前的充值权益金额。累计充值按实际正数入账更新。退款金额继续以基础额度表示，额度回收按退款比例乘以快照中的实际到账额度，渠道退款按基础额度与实付金额换算。退款恢复使用已经持久化的实际回收金额。

发起退款前，非强制退款要求余额足够回收基础及赠送额度。渠道退款进入待确认状态后，若渠道最终确认成功而余额已经下降，本地按剩余可用余额回收并记录实际扣减，不把这次处理改记为管理员强制退款。
