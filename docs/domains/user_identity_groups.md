# 用户身份分组

身份分组由管理员分配，入口位于分组管理的“身份分组”页签。身份是用户权益，普通分组继续承载路由、模型和访问权限。

<a id="membership"></a>
## 成员关系

`identity_groups` 保存三个固定身份：`bonus_5`（95折）、`bonus_10`（9折）、`ahhilai`（AHHilAI）。`user_identity_memberships` 以用户和类别为主键。两个折扣身份属于同一个类别（内部类别名仍为 `recharge`），每个用户最多一档；AHHilAI 属于定价类别，可以和折扣身份同时存在。

批量分配在事务内按用户 ID 顺序锁用户，检查全部用户存在，再替换或移除成员关系。移除操作匹配指定身份，所以移除 95折身份不会移除已经变成 9折的用户。修改前后的成员信息写入 `identity_group_changes`，事务成功后失效用户认证缓存。

身份组不授予普通分组访问权限。AHHilAI 的倍率为空时继承普通分组默认值，新普通分组自动出现在倍率表中。

<a id="pricing"></a>
## 消费倍率

billing 按以下顺序解析余额消费倍率，取第一个存在的值：

1. 个人专属倍率（`user_group_rate_multipliers`）。
2. AHHilAI 对该普通分组的覆盖倍率（`identity_group_rates`），可以是零。
3. 折扣身份成员的普通分组默认倍率乘以折扣：95折乘 0.95，9折乘 0.9。

三者都没有时使用普通分组默认倍率。折扣只作用在第三步，不会叠加到个人或 AHHilAI 倍率上。折扣系数集中定义在 `billing/identity_rates.go`，PostgreSQL 有效倍率查询由它生成 SQL，`/user/identity-groups` 也用同一份数据返回 `rate_discount`。

网关资金准入、结算、创作台、批量图片和用户分组价格展示使用同一有效倍率读取能力，查询失败返回错误。有效倍率直接读取数据库，身份变更后的请求读取新值。异步图片任务使用提交时保存的计费快照。团队请求按付款主体的身份解析。订阅承担的部分使用套餐和普通分组的原有倍率，不应用身份折扣；已解析的零倍率在订阅超额转余额时保持为零。独立售价模型的倍率固定为 1，同样不受折扣影响。

<a id="recharge"></a>
## 充值与退款

身份不提供充值赠送。正数余额兑换码和新的在线余额订单都按面额到账，仍然保存 `recharge_snapshot`，其中身份为空、赠送为零，这样到账与退款对所有记录使用同一种结构。赠送使用十进制计算，按 8 位小数四舍五入。

在线余额订单在下单时保存快照，付款和补单按照这个快照发放，支付内部兑换通过独立上下文传入快照。因此快照中记录了赠送的旧订单，付款时仍按快照到账。历史订单的空快照表示无加赠。管理员调账、并发兑换、订阅、注册赠送和返利转入使用各自的既有规则。

邀请返利基数是加赠前的充值权益金额。累计充值按实际正数入账更新。退款金额继续以基础额度表示，额度回收按退款比例乘以快照中的实际到账额度，带有历史赠送的订单会一并回收赠送部分；渠道退款按基础额度与实付金额换算。退款恢复使用已经持久化的实际回收金额。

发起退款前，非强制退款要求余额足够回收快照中的全部到账额度。渠道退款进入待确认状态后，若渠道最终确认成功而余额已经下降，本地按剩余可用余额回收并记录实际扣减，不把这次处理改记为管理员强制退款。
